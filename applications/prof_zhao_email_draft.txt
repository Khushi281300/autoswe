Recent work by Wang, Pradel, and Liu (ICSE 2026) showed that 29.6% of plausible agent patches behave differently from developer fixes under differential testing. To explore whether these suspect patches can be flagged at generation time without relying on developer reference oracles, I built a pilot framework evaluating static scope and syntactic contract checks across 724 agent patches from OpenHands, LearnByInteract, and CodeStory.

Our pilot experiments revealed an important empirical finding:
- Naive static checks flagged 47.3% of divergent patches and 50.0% of non-divergent patches, performing close to chance level (precision 34.6% vs. 35.9% base rate), driven largely by high false alarms in broad file-mention rules. In contrast, existing developer regression tests achieved 63.5% precision at a 7.5% false alarm rate.
- However, specific syntactic rules (such as public signature mutation and validation guard removal) demonstrated high specificity (~1.0% false alarm rate), and we observed a widespread commit-hygiene phenomenon where 27.8% of agent patches inadvertently commit scratch reproduction scripts into root directories.

These findings show that pure static rules cannot serve as a stand-alone rejection gate, and motivate my proposed Master's research: studying which oracle-free signals carry genuine predictive power and designing hybrid static-dynamic verification to reliably guide agent repair loops.
