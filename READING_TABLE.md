# Related Work & Literature Reading Table
## Automated Program Repair, SWE-bench Overfitting, and Oracle-Free Verification
**Prepared:** 4 October 2026 | **Author:** Khushi Shukla

Target: At least 12 papers reviewed with clear contrast against our proposed oracle-free gate approach.

| # | Paper Title | Authors / Venue | Core Method | Dataset / Benchmarks | Key Findings & Results | Critical Limitations | How Our Study Differs |
| :-: | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | *Are "Solved Issues" in SWE-bench Really Solved Correctly? An Empirical Study* (PatchDiff) | Replication pkg (Zenodo: 10.5281/zenodo.17074796) | LLM-based differential test generation to differentiate candidate patch from developer fix. | SWE-bench Verified (OpenHands, LearnByInteract, CodeStory) | Found significant divergence and test overfitting among benchmark-resolved patches. | Requires the oracle (human developer patch) and heavy test generation in Docker. Post-hoc evaluation only. | We design **oracle-free gates** runnable at generation time *without* knowing the gold patch. |
| **2** | *SWE-bench: Can Language Models Resolve Real-World GitHub Issues?* | Jimenez et al. (ICLR 2024) | Benchmark of real-world GitHub issues and test suites. | SWE-bench (2,294 tasks) | Pass rates initially <15%; now >40% with multi-agent scaffolding. | Relies on sparse repo unit tests; susceptible to test overfitting. | We evaluate patch validity beyond benchmark test suites. |
| **3** | *AutoCodeRover: Autonomous Program Improvement* | Zhang et al. (ISSTA 2024) | AST-based spectrum localization and LLM-guided patch generation. | SWE-bench | Higher localization precision reduces search space. | Does not verify behavioral invariants outside targeted methods. | We build lightweight syntactic/semantic gates to reject overfitted patches. |
| **4** | *Agentless: Demystifying LLM-based Software Engineering Agents* | Xia et al. (arXiv 2024) | Two-phase localization & repair without complex agentic loops. | SWE-bench Lite / Verified | Competitive performance with simple, transparent pipelines. | Lacks an invariant verification gate to prevent specification drift. | Our gates can be integrated into transparent pipelines like Agentless. |
| **5** | *REFINE: Iterative APR via Test Feedback* | Related Work | Iterative refinement driven by failing test feedback. | SWE-bench / Defect4J | Refinement improves local pass rate. | Can overfit to the test cases used for feedback. | Our gates enforce global contracts and scope bounds. |
| **6** | *PAFT: Patch-Aware Fine-Tuning* | Related Work | Fine-tuning LLMs on commit diffs and issue context. | GitHub commits | Enhances LLM diff generation structure. | Does not prevent runtime semantic regression. | We operate post-generation on arbitrary LLMs. |
| **7** | *Probe: Understanding LLM Patch Behavior* | Related Work | Dynamic probing of program state. | Defects4J / SWE-bench | Catches latent bugs. | Heavy runtime overhead. | Our Scope Gate is static AST analysis (instantaneous). |
| **8** | *SpecRover: Code Specification Guidance* | Related Work | Generates formal specs before repair. | SWE-bench | Reduces hallucinated fixes. | High prompt & LLM latency for spec extraction. | Lightweight, rule-based structural & contract gates. |
| **9** | *SWE-ABS: Abstract Specification Extraction* | Related Work | Abstract behavioral specs for SWE-bench. | SWE-bench | Flags unintended behavioral changes. | Requires complex oracle modeling. | Oracle-free checks based solely on pre-existing code & issue. |
| **10** | *UTBoost: Test-Suite Augmentation for APR* | Related Work | Test generation to enrich regression suites. | Python APR benchmarks | Reduces overfitting by increasing test coverage. | High execution overhead and flaky test generation. | We combine static scope checks with pre-existing tests first. |
| **11** | *Test Overfitting in LLM APR (arXiv 2511.16858)* | Related Work | Empirical characterization of test cheating and overfitting. | SWE-bench Verified | Quantifies silent regression rates in LLM APR. | Diagnostic only; does not provide an integrated gate. | We provide concrete, deployable verification gates. |
| **12** | *Prof. Zhao's APR Research (e.g., GECCO 2024)* | Zhao et al. | Search-based and automated program repair techniques. | APR benchmarks | Explores patch space search and overfitting reduction. | Search-space exploration can be computationally demanding. | Direct relevance to lab research; connects LLM repair to APR foundations. |
