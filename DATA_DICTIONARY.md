# Data Dictionary
## APR Overfitting Study & PatchDiff Replication Data
**Prepared:** 4 October 2026 | **Author:** Khushi Shukla

---

### 1. `PatchDiff/results/RQ34.csv`
Contains the 77 manually inspected and verified instances from the PatchDiff paper (RQ3 and RQ4).

| Column | Type | Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `tool` | `string` | `OpenHands`, `LearnByInteract`, `CodeStory` | The automated SWE agent that generated the patch. |
| `instance_id` | `string` | e.g. `django__django-16527` | The unique SWE-bench task identifier (`<repo>__<issue_id>`). |
| `diff_pattern` | `string` | `divergent`, `noalignment`, `supplementary_more`, `supplementary_change`, `absent` | Structural/semantic divergence classification: <br>• **`divergent` (36):** Divergent logic at the same program location.<br>• **`noalignment` (16):** Patch applied in an entirely different file/component than developer fix.<br>• **`supplementary_more` (13):** Model patch edits extra locations beyond developer patch.<br>• **`supplementary_change` (8):** Model patch edits alternative locations while partially overlapping.<br>• **`absent` (4):** Model patch omits key changes made by the developer. |
| `correctness` | `string` | `incorrect_regression`, `incorrect_partial`, `incorrect_irrelevant`, `incorrect_erroneous`, `uncertain`, `correct_invaliddt`, `correct_irrelevant` | Ground-truth verdict from manual inspection:<br>• **`incorrect_regression` (11):** Breaks pre-existing tests or valid invariants.<br>• **`incorrect_partial` (6):** Only partially solves the issue; misses required edge cases.<br>• **`incorrect_irrelevant` (3):** Edits unrelated code or bypasses root cause.<br>• **`incorrect_erroneous` (2):** Directly erroneous code.<br>• **`uncertain` (51):** Plausible alternative implementation; human annotators could not decisively prove incorrectness.<br>• **`correct_invaliddt` (2):** The differential test generated was invalid/unreasonable; the model patch is actually correct.<br>• **`correct_irrelevant` (2):** Alternative valid fix that touches a different layer. |

> [!IMPORTANT]
> **Sampling Bias & Negative Set:** The 77 instances in `RQ34.csv` were selected because PatchDiff generated differential tests for them. To prevent sampling bias when computing False Positive Rates, we must sample **resolved instances where no differential tests were found** (`RQ2_*_difftests.json` where `differential_tests == []`) as our true negative set.

### 2. `PatchDiff/results/RQ1_*_runall.json`
Files: `RQ1_OpenHands_runall.json`, `RQ1_LearnByInteract_runall.json`, `RQ1_CodeStory_runall.json`.

Stores regression test failures when running the existing developer test suite on the patched codebase.
- **Top-level Key:** `instance_id` (e.g. `sympy__sympy-24443`).
- **Fields:**
  - `oracle_pass_model_fail`: List of test cases that PASS on the developer patch but FAIL on the agent's patch (e.g., `["sympy/combinatorics/tests/test_homomorphisms.py::test_check_homomorphism"]`).
  - `difference`: Type of difference (e.g. `functionality`).

---

### 3. `PatchDiff/results/RQ2_*_difftests.json`
Files: `RQ2_OpenHands_difftests.json`, `RQ2_LearnByInteract_difftests.json`, `RQ2_CodeStory_difftests.json`.

Stores the LLM-generated differential tests for 217 instances across the tools.
- **Top-level Key:** `instance_id` (e.g., `astropy__astropy-14995`).
- **Value:** Array of test generation attempts. Each object contains:
  - `idx`: Integer attempt index (0 to N).
  - `gen_test_file`: Python test file content generated by the LLM.
  - `differential_tests`: List of test functions that successfully differentiate the model patch from the oracle patch (e.g. `["tests/test_x.py::test_case_1"]`). If empty `[]`, no differential test succeeded.

### 4. `PatchDiff/data/tool_results/<tool_name>/`
Contains the agent patch outputs from the SWE-bench benchmark evaluations:
- **`all_preds.jsonl`**: JSON Lines file where each record has:
  - `instance_id`: Unique benchmark task ID.
  - `model_patch`: Unified diff string generated by the agent.
  - `model_name_or_path`: Underlying LLM model identifier.
- **`results.json`**:
  - `resolved`: List of `instance_id`s that passed SWE-bench acceptance tests ($T_{fail \to pass} \land T_{pass \to pass}$).
  - `no_generation`: Instances where no patch was produced.
  - `no_logs`: Instances where execution logs could not be retrieved.

---

### 5. `PatchDiff/data/dataset/swebench_verified/`
The Hugging Face dataset for SWE-bench Verified (500 instances).
- `instance_id`: Task identifier.
- `repo`: Repository path (e.g. `django/django`).
- `base_commit`: Git commit hash representing the base state before bug fix.
- `problem_statement`: Original issue description and stack traces reported by users.
- `hints_text`: Issue comments/hints provided before fix was authored.
- `patch`: The developer reference fix (gold patch).
- `test_patch`: The test case added by developer to reproduce the issue.
- `FAIL_TO_PASS`: List of test cases that initially fail on base repo and must pass with fix.
- `PASS_TO_PASS`: List of pre-existing test cases that must continue to pass.
- `version`: Version tag of the repository.
- `environment_setup_commit`: Commit hash used to build environment.
